
DovahKit's  script engine relies on  cross-thread tasks in order to  coordinate 
a variety of editing operations between the client and worker threads. However, 
care must be taken to avoid some nasty  edge-cases that can arise when the user 
force-kills the script -- that is, when the user calls an abort.

Ordinarily, when the script thread sends  a blocking task to the client thread, 
it will perform  an atomic wait until that task has been marked  as "seen." The 
task would ordinarily be marked as "seen"  after it has been executed; however, 
if an abort has  been called, the task will  not be executed.  Accordingly, the 
coordinator subsystem needs to ensure  that if an abort is called, any blocking 
task that is pending execution gets marked as "seen" without being executed.

There are consequences for non-blocking tasks as well, however. When the worker 
thread is in  between executing units of  Lua code, in its idle  cycle, it will 
perform an atomic wait until the task  queues for non-blocking tasks are empty. 
If an abort has been  called, these queues  will never  be processed; thus, the 
coordinator  subsystem must clear the queues in the main thread  handler, along 
with discarding any  blocking tasks, in order to ensure  that the worker thread 
does not deadlock.
