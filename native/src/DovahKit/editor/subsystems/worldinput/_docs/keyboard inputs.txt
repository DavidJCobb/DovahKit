
On an American  keyboard layout, the plus  symbol can only  be typed by holding 
the Shift key and pressing the equal  sign key (or by using the plus key on the 
number pad, but ignore that for a moment and let me make my point). If you hook 
the keypress events on a widget and  compare pressing the "=" key when Shift is 
and isn't held, Qt will produce the following results:

   Pressing "=":

      QKeyEvent::key()              == Qt::Key::Key_Equal
      QKeyEvent::nativeVirtualKey() == VK_OEM_PLUS // 0xBB
      QKeyEvent::nativeScanCode()   == 0x0D

   Pressing "Shift + =":

      QKeyEvent::key()              == Qt::Key::Key_Plus
      QKeyEvent::nativeVirtualKey() == VK_OEM_PLUS // 0xBB
      QKeyEvent::nativeScanCode()   == 0x0D

Qt's keyboard APIs prioritize letting you know what symbol would be produced by 
the user's keypress  were it taking place "in context"  and in a text box; Qt's 
input handling  will check what modifier  keys are held, and  so on. This makes 
sense: the primary purpose of Qt's keyboard APIs is to enable text entry within 
Qt's various widgets as well as within custom widgets. However, this makes Qt's 
APIs utterly unsuitable for use in tasks like defining keyboard shortcuts. If a 
user wishes for some program action to occur when they hold Shift and press the 
equal sign key, I need to display that to them as "Shift + =", not "Shift + +".

Unfortunately, this means that the only solution is to fall back to the Windows-
specific values for key input: the virtual key code and the scan code.

Given a virtual key code (hereafter: VK),  you can identify the scan code using 
this call:

   auto scan = MapVirtualKey(vk, 4);
   if (scan == 0)
      //
      // The value "4" doesn't work on older versions of Windows, e.g. XP
      //
      scan = MapVirtualKey(vk, MAPVK_VK_TO_VSC);

Given a scan code, you can identify the key name, though that's more tedious:

   TCHAR buffer[20];
   auto len = GetKeyNameText((LONG)scan << 16, buffer, sizeof(buffer));
   //
   // The API design requires you to shift the scan code into the high 16 bits.
   //
   QString name;
   if (len) {
      if constexpr (std::is_same_v<TCHAR, WCHAR>) {
         name = QString::fromUtf16((const char16_t*)buffer, len);
      } else {
         name = QString::fromLocal8Bit((const char*)buffer, len);
      }
   }
