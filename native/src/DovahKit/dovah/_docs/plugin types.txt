
Skyrim's game data is defined in what are commonly called "plug-in" files. Such 
files can come in three basic types, which are not (all) mutually exclusive.

"Masters" are used by Bethesda for  finished works suitable for public release; 
compare to "master recordings" in audio. In practice, the Creation Kit that was 
shipped to the public does  not allow the editing  or saving of masters, so the 
modding community has generally avoided saving files as masters unless doing so 
was necessary for the file to function properly in-game.

"Plug-ins" were, traditionally, the only files that public builds of Bethesda's 
Creation Kit could save;  they are thus the de-facto standard for virtually all 
mods. This is not purely a semantic difference: the game has different behavior 
when loading  masters versus plug-ins, with  the most notable  difference being 
that all ObjectReferences  (REFRs and similar) defined  inside of a plug-in are 
permanently persistent, regardless of whether hhey have been flagged as such in 
the file data. Additionally, the Creation  Kit doesn't allow files to rely on a
plug-in as a dependency, though the game engine itself doesn't enforce any such 
limitation.

"Light" files were introduced with Skyrim Special Edition, and exist as a means 
of cramming a larger amount  of content into a  smaller load order. Light files 
share the  0xFE load order  slot at run-time,  with the next  three hexadecimal 
digits indicating  which light file a  form originates  from. Both masters  and 
plug-ins can be light.

A file's type is indicated by both its file extension and the flags in its file 
header, with the choice of extension overriding any flags:

 - *.ESM files are always masters (Elder Scrolls Master).
 - *.ESL files are always light masters (Elder Scrolls Light).
 - *.ESP files' types depend on the file header flags.

In various places the term "master" is also used as a synonym for "dependency," 
with a file's contained list of dependencies being called its "master list." In 
these contexts, there is no direct antonym to "master."


===  Miscellaneous information on light files =================================

Light files' "shared load order slot"  behavior isn't actually supported within 
the file format itself, or within the Creation Kit. Within a file, form IDs are 
always encoded  as if neither  the file nor its  dependencies are  light. As an 
example, a light file with two non-light  dependencies and one light dependency 
would use load order prefix 03 for its forms, with its light master having load 
order prefix 02.  The Creation Kit  treats form  IDs the same way,  most likely 
because doing so is much easier.

DovahKit will load light files' forms into the 0xFE slot at run-time in mimicry 
of the actual game.  DovahKit is not alone in this regard; xEdit does the same.


===  Different perspectives on plug-ins =======================================

Some believe that plug-ins were meant for work-in-progress files only, and that 
their handling of ObjectReferences is intended as a debugging aid. Because that 
handling of persistence can cause large-scale mods to contribute heavily to the 
game's reference handle limit (a cap on how many refs can be retained in RAM at 
any one time), it's believed that masters are meant for finished works and that 
masters should be preferred even for mods.

It has been noted by others that officially released mods published by Bethesda 
in venues such as the Steam Workshop have been released as plug-ins. Bethesda's 
games have historically forced masters to load before plug-ins  (new games just
hardcode a specific load order for official content). These facts have led some 
to think that plug-ins are explicitly meant to be used for mods, with differing 
persistence behaviors being meant as "training wheels."
